# Architecture and Data Flow

honeyagent runs as a single-binary security airlock in front of retrieval augmented generation (RAG) pipelines and autonomous agent runtimes. It uses active deception to identify adversarial probing and unauthorized data access.

## Core subsystems

The engine comprises five internal subsystems:

1. **Canary Engine**: Generates cryptographic canary tokens and embeds them inside realistic synthetic documents.
2. **Decoy Tool Sentinel**: Injects deceptive administrative tool definitions into agent context and intercepts execution calls.
3. **Detector and Stream Scanner**: Analyzes prompts, retrieved vector context, and model output streams for token signatures.
4. **Countermeasure Engine (Tarpit)**: Quarantines compromised sessions, serving plausible synthetic text and introducing latency delays to waste attacker resources.
5. **SIEM and Notification Dispatcher**: Exports ArcSight Common Event Format (CEF) and Elastic Common Schema (ECS) syslog records alongside Slack and PagerDuty alerts.

## Cryptographic token format

Each token generated by the canary manager follows this layout:

`CANARY_v1_<encoded_payload>_<hmac_signature>`

- **Prefix**: Identifies the token namespace (`CANARY_v1`).
- **Encoded payload**: Base64URL-encoded JSON structure containing document ID, category, vector store label, timestamp, expiration, and random nonce.
- **HMAC signature**: Hex-encoded HMAC-SHA256 computed using a 32-byte master secret key over the encoded payload string.

Validation uses `crypto/subtle.ConstantTimeCompare` (via `hmac.Equal`) to eliminate timing side-channel attacks.

## Airlock reverse proxy operation

The proxy listens on a dedicated port (default `8088`) and forwards clean requests to the upstream server (default `http://localhost:8000`).

When an attacker retrieves a chunk containing a canary token:
1. The scanner intercepts the token before it reaches the client.
2. The session identifier is added to the quarantine table.
3. The real response is replaced with synthetic text from the tarpit.
4. Subsequent calls from the same session bypass the upstream server entirely.
